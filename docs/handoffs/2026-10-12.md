## Gotchas for the next agent

- **A migration on `main` halts the scheduled sync** until Neon is migrated (the sync refuses a schema behind `main`). This happened 10-06 18:55–22:21. Merge migration PRs only in a window where Neon can be migrated right away.
- **Auto mode blocks production steps** (reads of Neon, `alembic upgrade`, deploys) even when asked in chat; only a permission rule or turning auto mode off allows them. The owner can also run a command with the `!` prefix.
- **The Neon CLI is now `neon`** (v8), not `neonctl`: `neon connection-string --project-id sweet-dew-33937746 --database-name internship_finder --role-name internship_finder`. Never print the result.
- **Deploy order**: migrate → Render (`render deploys create srv-dastve60tbcc7392dfgg --commit <sha> --wait`) → Vercel from a clean detached checkout (`npx vercel deploy --prod`), then `reevaluate` if a rules or scoring version changed.
- **Activating sources** without the UI: the app's own services (`update_source`, `add_from_catalog`, `add_from_discovery`) in a short script with `DATABASE_URL` set, then `python -m app.cli sync-source <key>`. Never raw SQL.
- **CI**: Postgres comes from `public.ecr.aws/docker/library/postgres:18`. The docs guard requires feature branches to set `docs/status.json` development and CI changes to update `docs/development.md`.
- **Parallel PRs** collide on CHANGELOG, PROJECT_STATE, README and status.json; resolve by keeping every entry and re-running `python scripts/check_docs.py --write-status`.
- **The machine is memory-constrained**: run Vitest with `--maxWorkers=2` and Playwright with `--workers=1`; never `taskkill /IM node.exe`; keep at most about 4 agents running.
- **`smartrecruiters:eurofins`** sometimes fails with "posting count changed mid-walk"; it fails safe and recovers next run.
- Leave the untracked `gemini.md` untouched.
